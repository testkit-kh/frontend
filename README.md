# Чистый берег — прототип

Космохакатон, задача «Развитие экологического проекта „Чистый берег“».
Фронтенд-прототип: карта загрязнений на спутниковой подложке, два контура —
волонтёр и сотрудник ООПТ.

```bash
pnpm install
pnpm run dev
```

## Что уже работает

**Вход и регистрация** (`/login`, `/register`). Поля те же, что уйдут в API:
почта, пароль, роль. У волонтёра — дата рождения (порог 14 лет), у сотрудника —
название ООПТ, ИНН и кадастровый номер. ИНН проверяется контрольной суммой ФНС
прямо в форме, кадастровый номер — по формату. Сессия лежит в localStorage;
настоящий JWT приедет с бэкендом.

**Карта** (`/map`) — главный экран для обеих ролей. Спутниковые тайлы Esri World
Imagery без ключа, подписи поверх из CARTO, границы ООПТ из OpenStreetMap.
Метка окрашена по статусу и несёт глиф типа — свалка или разлив. Разлив
рисуется полигоном: у пятна есть площадь, точкой её не передать.

- Волонтёр видит подтверждённые точки и свои — на проверке. Чужая предложка ему
  недоступна принципиально: иначе спам одного человека станет картой для всех.
- Сотрудник видит всё внутри своей ООПТ, включая отклонённое.
- Волонтёр добавляет гипотезу: метку кликом или контур пятна по вершинам.
- В карточке точки — место (Nominatim), условный маршрут от ближайшего
  населённого пункта (OSRM) и запись на субботник.

**Предложка** (`/moderate`) — экран сотрудника ООПТ. Сплит-скрин: слева то, что
прислал волонтёр, справа тот же участок со спутника. Три решения: подтвердить,
отклонить, «требуется облёт дроном». Третья кнопка — не вежливость: без снимка
или под облаками первые две одинаково наугад, и любая испортит данные.

## Данные

Демо-данные настоящие настолько, насколько это возможно без бэкенда.

```bash
pnpm run data     # всё сразу, ~2 минуты
```

| Шаг                         | Источник         | Что делает                                                         |
| --------------------------- | ---------------- | ------------------------------------------------------------------ |
| `pnpm run data:territories` | Nominatim (OSM)  | Границы четырёх прибрежных ООПТ → `static/data/territories.json`   |
| `pnpm run data:coastline`   | Overpass (OSM)   | Береговая линия вокруг них → `scripts/cache/coastline.json`        |
| `pnpm run data:seed`        | —                | 42 гипотезы **внутри** этих полигонов → `static/data/reports.json` |
| `pnpm run data:enrich`      | Nominatim + OSRM | Название места и маршрут от ближайшего города к каждой точке       |

Территории: Утриш, Куршская коса, Сочинский НП, Земля леопарда.

Три решения, которые стоит объяснить:

- **Скриптами, а не запросами из приложения.** Nominatim просит не больше одного
  запроса в секунду и представляться в User-Agent. На такой основе нельзя
  строить экран, который открывают пользователи: забираем один раз и кладём
  результат в репозиторий.
- **Точки проверяются на попадание в полигон** тем же лучевым алгоритмом, каким
  это будет делать PostGIS. Гипотеза вне границ ООПТ — это баг, и увидеть его
  надо при генерации данных, а не на защите.
- **Свалка не может оказаться в море, а разлив — на скале.** Море в OSM не
  нарисовано полигоном, есть только `natural=coastline`, но у неё есть
  соглашение о направлении: суша слева по ходу линии, вода справа. Отсюда
  классификатор в `scripts/coastline.mjs` — он же следит, чтобы контур пятна
  целиком лежал в воде, а не половиной заливал пляж. Свалки ставятся не дальше
  6 км от берега: проект называется «Чистый берег», мусор в тридцати километрах
  вглубь материка формально внутри ООПТ, но к задаче отношения не имеет.
- **Генератор детерминированный** (mulberry32 с фиксированным seed). Иначе
  скриншоты в презентации разъедутся с тем, что показывают со сцены. Статусы
  раздаются квотой, а не броском на каждую точку: при броске у отдельной ООПТ
  запросто выпадает ноль гипотез на проверке — и предложка открывается пустой.

Границы и маршруты упрощаются по Рамеру — Дугласу — Пекеру
(`scripts/simplify.mjs`): у Сочинского нацпарка контур приезжает с 8500
вершинами, это 200 КБ на линию толщиной в полтора пикселя.

## Чего пока нет

- **Онбординг с флеш-карточками.** Флаг допуска (`onboarded`) в модели заведён,
  но всегда `true`: ставить `false` без экрана обучения — значит запереть
  зарегистрированного волонтёра в тупике. Переключается тем же коммитом, что
  добавит онбординг.
- **Бэкенд.** Гипотезы живут в памяти вкладки: перезагрузка возвращает исходный
  набор. Модели и эндпоинты авторизации пишутся отдельно (FastAPI + PostGIS),
  роли на фронте названы так же — `volunteer` / `staff`.
- **Фотографии с места.** В сплит-скрине слева заглушка, явно подписанная
  «демо-изображение»: настоящих фото взяться неоткуда, а выдавать рисунок за
  снимок с места нельзя.

## Стек

SvelteKit 2 · Svelte 5 (runes) · Tailwind 4 · MapLibre GL + svelte-maplibre ·
`@lucide/svelte`

Приложение целиком клиентское (`ssr = false` в `(app)/+layout.ts`): сессия лежит
в localStorage, и отрисованная на сервере страница всё равно не знает, кто её
откроет.
